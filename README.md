# 風管處作業風險準則規範之 RAG 檢索優化研究 (POC)
(無內部營運資訊)
記錄在風險管理處針對「作業風險準則、內部控制規範與審查細則」進行智慧檢索增強生成（RAG）時，為解決檢索精度不足、引發模型幻覺所進行的技術評估與迭代歷程。

---

## 1. 研究動機與業務痛點

風險管理處內部之作業風險手冊與準則充滿**特定法規條號（如 OP-RISK-302）、內部控制編號與絕對數值門檻（如通報金額、審批權限級距）**。
* **主要痛點：** 純語意向量檢索（Dense Retrieval）容易因向量相似度模糊，召回「語意相近但適用部門不同或條款代碼錯誤」的文本，導致後續生成回答時引用錯誤準則，產生致命合規風險。
* **研究目標：** 探索如何在保留第一線人員口語提問意圖的同時，精確鎖定作業風險條文代號與關鍵字，並維持合規稽核所需的高可解釋度。

---

## 2. 迭代歷程與方法對比 (Iteration Log)

在 POC 階段針對內部模擬準則進行三次架構迭代與測試：

| 迭代版本 | 採用架構 | 優點 | 致命缺點 / 淘汰原因 |
| :--- | :--- | :--- | :--- |
| **Phase 1: Baseline** | 純 Dense 向量檢索 (MiniLM / BGE) | 語意匹配度高，能理解前線口語提問 | **條號精確命中率僅約 50%**，常混淆不同層級的風管審批規範 |
| **Phase 2: 關鍵字補強** | 純 Sparse 檢索 (BM25) | 條號與特定風管術語命中率達 85% 以上，速度極快 (<2ms) | **完全喪失語意理解**，遇到同仁以口語描述事件情境時無法有效召回 |
| **Phase 3: 雙路混合架構** | **BM25 + Dense + RRF + Cross-Encoder** | **條號與關鍵條件精確度達 98%**，兼顧精確條號與情境意圖 | 增加約 30ms 重排延遲，但在高合規代價的風管決策下完全合理 |

---

## 3. 現階段技術抉擇 (Decision & Trade-offs)

經多次實驗驗證，現階段選用 **Phase 3（雙路混合檢索 + Cross-Encoder 重排）** 作為作業風險規範的核心解方：

1. **採用 RRF 排名融合替代分數加權：**  
   BM25 得分與語意 Cosine 分數尺度差異大，手動設定加權超參數極易受文件長度影響；採用 **RRF（倒數排名融合）** 能基於次序進行尺度無關（Scale-invariant）的穩定整合。
2. **合規精確度優先於毫秒級延遲（Precision over Latency）：**  
   引入 Cross-Encoder 雖增加約 30ms 運算耗時，但在作業風險與法規審核場景中，「檢索精準度（Context Precision）」的優先級遠高於極致響應速度。
3. **安全防護截斷門檻（Guardrails）：**  
   若重排後的最高候選段落相關度低於設定閾值，系統直接回覆「查無對應作業風險規範」，嚴禁模型自由推測或編造合規條文。

## 4. 未來持續研究方向 (Next Steps)

* **[方向一] 跨頁審批權限表切塊：** 目前純文字切塊對橫跨多頁的「作業風險通報權限表」與矩陣式規程解析仍有斷裂問題，預計評估整合結構化 Markdown 表格辨識。
* **[方向二] 地端高併發推論部署：** 評估接入 `vLLM` 框架加速自建開源模型（如 Qwen-2.5 / Llama-3）之 Serving 吞吐，確保敏感風管機密數據不出網。
* **[方向三] 自動化合規評估管線（Ragas）：** 針對作業風險常見問題建立 Golden Dataset，持續監控檢索忠實度（Faithfulness）與答案相關度。
